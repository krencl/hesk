# ADR 0024: Game tags and the statistics filter

Status: accepted (2026-10-23)

## Context
The old application had two kinds of tags: play tags (`tag.type = round`, e.g. place and occasion; in the new application `PlayTag`, ADR 0004; table `play_tag`, join with a play `play_play_tag` – consistent with `game_tag`/`game_game_tag`) and game tags (`type = game`, table `tag_game`: "Rychlovka" (quick game), "Strategie" (strategy), "Karetní" (card), …). The import discarded game tags and statistics could not be narrowed. The old application could filter statistics by game tags (`gameTag`, `gameTagNot`).

## Decision
- **Game tags belong to the game in the catalog** (ADR 0023), not to the party: entity `GameTag` (`name` unique, case-insensitive), relation `Game::tags` (M:N, table `game_game_tag`). They are separate from play tags (`PlayTag`, per party), so that "Rychlovka" is not confused with "Skalka" (a place).
- **Editing is shared data**, so only a game administrator changes them (`PUT /api/games/{id}`, field `tags`), and, when a game is being created, whoever creates it (`POST /api/parties/{id}/games`). In the game form the "Tagy" (Tags) field is in the lockable part. The API response carries `tags` (sorted, case-insensitive); nonexistent tags are created on save.
- **Tag lists:** `GET /api/game-tags` (all in the catalog, autocomplete in the form) and `GET /api/parties/{id}/game-tags` (only tags of games enlisted in the party, the statistics filter offer).
- **Statistics filter:** `GET /api/parties/{id}/stats?games[]=<id>&tags[]=…&excludeGames[]=<id>&excludeTags[]=…` (`StatsFilter`). A play passes when its game is among the selected games **or** has **at least one** of the selected tags (`games`, `tags`; with no selection everything passes) **and at the same time** the game is not among the excluded games and has **none** of the excluded tags (`excludeGames`, `excludeTags`; exclusion takes precedence). It applies to players' wins and to most played games (`PlayRepository::winsPerPlayer/topGames`, `EXISTS` subqueries with unique aliases). Unlike the old application, the selection of games and tags is not combined with "and" but with "or", because the user picks them in a single field.
- **Statistics UI:** a single search field styled like the game list ("Hra nebo tag", Game or tag) searches in the party's games (server, `GET /games?q=`) and in the tags of the party's games (`GET /parties/{id}/game-tags`, diacritics- and case-insensitive); the results replace the charts; a focused empty field immediately offers all tags (after a selection the offer stays open, without the selected ones). Each result row has "+" and "−" buttons on the right, a tap on the whole row acts like "+". A selected game/tag is added as a "+" label (only such games) or "−" label (without them), a tap on the label toggles it, the cross removes it. The filter is shown only when the party has played some game; an empty party shows only the sentence "Ještě jste nic neodehráli, je čas to napravit." (You haven't played anything yet, time to fix that.) and a filter that finds nothing shows the message "Žádná odehraná hra neodpovídá filtru." (No played game matches the filter.)
- **Import** (ADR 0012) carries `tag_game` over to games in the catalog (matched by name, link key `gametag` = old tag id); tags are only added, manual changes in the new application are not removed.
- Migration `Version20261028000000`.

- **Address and sharing:** statistics live at `/parties/:id/stats` (the party ID is in the address, the page follows the address, not the active party; a foreign or nonexistent party shows a message; `/stats` redirects to the active party, switching the party in the menu moves the page under the new party without a filter). The filter is in the address parameters (repeated `games`, `excludeGames` = game ids, `tags`, `excludeTags` = names), so it can be shared by a link; filter changes rewrite the address (`replace`, no history entries). The address contains only game ids, label names are looked up (`GET /parties/{id}/games/{gameId}`, `Hra #id` ("Game #id") until it arrives). Labels have a stable order (games by id, tags by name) so they do not jump when toggling "+" ↔ "−".
- **Clearing the filter:** when any filter is set, there is a "Zrušit filtr" (Clear filter) button among the labels. Exclusion ("−") is red (`--error`), selection "+" blue.

## Consequences
- A change of a game's tags shows up in all parties; a party member does not change the tags of a shared game (only a game administrator).
- Typed search text and an open offer are not stored in the address, only the selected labels.
- Play tags are not yet reflected in the statistics filter (the old application could do it – `roundTag`); it can be added the same way.
