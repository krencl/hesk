# ADR 0020: Game image upload with square cropping

Status: accepted (2026-10-21)

## Context
The game image was only a URL (ADR 0004, 0011) and covers from the old application are local files without upload. In game management the image should be uploadable with a square crop chosen right away, because it is displayed as a square everywhere (list, detail, statistics) (`object-fit: cover`).

## Decision
- **Editor in the browser:** choosing a file opens the popup `ImageCropPopup` (same base as `SelectPopup`) with the library `react-easy-crop`: square crop, drag and zoom (slider, pinch on touch). After "Použít" (Apply), `cropToBlob` (canvas) cuts out the crop, scales it to 600 × 600 px and encodes it as **WebP** (quality 0.85, transparency onto white), so only tens of kB are transferred and the browser handles EXIF orientation. A browser that cannot encode WebP (Safari on iPhone, the canvas then silently returns PNG) sends JPEG (quality 0.9) and the server converts it to WebP. This path can also be forced in Chrome by adding `?coverFormat=jpeg` to the game form address (e.g. `/games/5/edit?coverFormat=jpeg`).
- **Upload:** `POST /api/parties/{id}/game-images` (multipart `file`, a party member may, like the rest of game management) returns `{url}`. `CoverStorage` verifies that it is WebP, JPEG or PNG (by content, not extension), is square, is 100–2048 px and at most 2 MB (otherwise 422). WebP is stored unchanged, JPEG/PNG is converted by `GdWebpConverter` (GD, quality 85, transparency onto white); it is stored under the `sha1` of the resulting content (same file = same address, no duplicates).
- **PHP requirement:** `ext-gd` with JPEG, PNG and WebP support (Debian/Ubuntu `php-gd` has it, in Docker `docker-php-ext-configure gd --with-jpeg --with-webp`). Without it a JPEG/PNG upload returns error 500 (WebP from Chrome/Firefox works even without it). **I wrote the conversion blind**: the dev container has GD without JPEG/WebP, so tests use `FakeWebpConverter` and `GdWebpConverterTest` is skipped here; run it on an image with GD.
- **Storage:** `web/uploads/covers/<sha1>.webp` (parameter `app.uploads_dir`, in tests `backend/var/test-uploads`), address `/uploads/covers/…`; git-ignored. The built-in PHP server serves files from `/uploads/` like `/static/` (`web/index.php`); **in production the web server must serve `web/uploads/` at `/uploads/` and the directory must survive deployment** (unlike `web/static`, which the build overwrites).
- **Game form:** the "Obrázek" (Image) field shows a preview and the buttons Nahrát/Změnit (Upload/Change) and Odebrat obrázek (Remove image); after upload `imageUrl` is only filled in and saved together with the game. Manual URL entry **is gone**: `imageUrl` may only be the address of a stored image (`/uploads/covers/<sha1>.webp`, `CoverStorage::URL_PATTERN`), otherwise the API returns 422. Internally there is thus a single format.
- **Migration of old covers:** 68 files from `/static/covers/` (128 games) were converted one-off to WebP 512 × 512 (they were already square, the image center = the crop that `object-fit: cover` showed) into `web/uploads/covers/` and `game.image_url` was rewritten; the original files remained as a backup, since then moved from `frontend/public/covers/` to `/legacy-covers/covers/` (git-ignored) so that Vite does not copy them into every build (13 MB in `web/static/`); no game references them any more (`image_url` is only `/uploads/…` or empty). The conversion ran in headless Chromium (canvas → WebP), because PHP in the dev container has no GD with WebP/JPEG. **The import from the old application no longer copies covers** (`--covers-*`, `--no-covers`, `LEGACY_COVERS_DIR` are gone) and does not overwrite `image_url`.

## Consequences
- An uploaded file that ends up assigned to no game (or after an image replacement) stays on disk; cleanup of orphaned files does not exist yet.
- A game without an uploaded image shows a placeholder image; after a new import from the old application the images must be uploaded manually.
- `web/uploads/` must be backed up too, not just the database.
