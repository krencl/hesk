# CLAUDE.md – HESK (board game play logs)

Web application for recording board game results and party player statistics. Communicate with the user in **Czech**; write all documentation, code comments and commit messages in English. Commit all changes to git; record architectural decisions in `docs/adr/` (see `docs/README.md`).

## Repo structure
- `web/index.php` – main router in the root (`/api` → Symfony with project_dir `backend/`, otherwise the SPA `web/static/index.html`); `web/static/` – static files = frontend build (git-ignored).
- `backend/` – Symfony 7.4 LTS, PHP ≥ 8.4, Doctrine ORM (MariaDB 11), PHPUnit. REST API under `/api`.
- `frontend/` – React 19 + TypeScript + Vite, TanStack Query, React Router, Vitest.
- `docs/` – ADRs + notes. The original directories `/hesk-dev-old` (prototype) and `/hesk-original` (old production, Node/RethinkDB) no longer exist (deleted 2026-10-24); only historical references remain in the ADRs and `docs/prototype-notes.md`.

## Commands
- The import from the old application was removed (ADR 0029; restore it from git, the last commit containing it is `a4d9414`). After changing entities, run `cache:clear` before `doctrine:migrations:diff`/`schema:*` with `--no-debug`, otherwise stale mapping metadata is read.
- Backend: `cd backend && composer install && php bin/phpunit` · dev server from the root: `php -S 127.0.0.1:8000 -t web web/index.php` (API + static files + SPA fallback) · DB `docker compose up -d database` + `php bin/console doctrine:migrations:migrate`.
- Frontend: `cd frontend && npm install && npm test` · `npm run dev` (proxy `/api` → :8000) · `npm run build` (including `tsc`, output to `/web/static`).
- Configuration: each clone has its own git-ignored `.env` (**contains secrets – never commit or print it**), loaded by Symfony via the symlink `backend/.env.local` (`DB_*`, `OAUTH_GOOGLE_*`). See ADR 0006. **This clone (`/workspace/hesk-dev`) uses the separate DEV database (`hesk-dev`, user `hesk-dev`, `APP_ENV=dev`); the production clone `/workspace/hesk` uses DB `hesk` / user `hesk` (`APP_ENV=prod`) – ADR 0032 (supersedes the "no dev DB" part of ADR 0029).** Before any DB write or schema command, check that `backend/.env.local` really points to `hesk-dev` (`grep DB_DATABASE .env`, never print the other values). Dev DB: schema commands and migrations may be run here. Never run anything in `/workspace/hesk` against the production DB (no `DELETE`/`DROP`/`TRUNCATE`/`schema:*`/`migrations:migrate`) – migrations of a new release are run by the owner (checklist in ADR 0029). Manual queries against production: read-only (`SELECT`) and only if explicitly asked. **Production** (https://hesk.krencl.cz/): committed defaults in `backend/.env.prod`, secrets in `backend/.env.prod.local` (template `.env.prod.local.example`), deployment checklist in ADR 0029. `POST /api/auth/dev-login` (the login form in Vite dev mode) is for `dev`/`test` only and writes to the dev DB (it may create a user), which is fine here.

## Backend – overview
- `src/Entity` – `User (role in `roles`; `ROLE_GAMES_ADMIN` = games admin), Party, PartyMember (nickname within the party `nickname` × account nickname, `displayName()`, ADR 0030), PartyInvitation, Player (party player, also a guest without an account), Game (shared game catalog, ADR 0023), PartyGame (game enrolled in a party + the game's own players), GameAddon (expansion), GameCharacter (characters), GameTag (game tags, ADR 0024), PlayTag (play tags, table `play_tag`, join table `play_play_tag`), GameSession, Play, PlayResult`.
- `src/Domain` – pure logic: `ResultCalculator` (ranking/winners by `ScoreType`), `PlayerInput/Outcome`, `NameKey` (name key insensitive to case and diacritics, ADR 0025 – **every name comparison goes through it**), `NamedItems` (trimming/deduping lists of names, matching entities by key), `Exception/DomainException` (→ HTTP 422).
- `src/Service` – `CoverStorage` (game image upload), `PlayService` (create/update/delete a play), `GuestMerger` (guest → member, ADR 0018), `PlayMover` (moving a play to another party, ADR 0028), `SessionAssigner` (24h sessions, number suggestion, manual number; ADR 0013), `Bgg/BggClient` + `BggCatalog` (game search: party games → `bgg_game` cache → BGG API, `BGG_API_TOKEN`; ADR 0021), `Presenter` (entities → JSON). `php bin/console app:user:role <e-mail> [ROLE] [--remove]` assigns a role (games admin).
- `src/Repository` – queries outside the entities: `GameRepository` (game search/statistics, `preloadDetails` against N+1), `PlayRepository` (play pagination with `preloadDetails`, statistics, `countForPlayer`), `GameSessionRepository` (`findOneByNumber`, `findAccepting` = the 24h window mirrors `GameSession::accepts`, `maxNumber`), `PartyGameRepository` (`findByPlayer`), `GameTagRepository`/`PlayTagRepository` (`findOrCreate` of tags by `NameKey`), `BggGameRepository`, `PartyRepository`, `StatsFilter`. Collections that the Presenter reads for lists are loaded in bulk (fetch join per collection), not lazily one by one.
- `src/Controller` – thin controllers (`Party, Game, Bgg, Play, Tag, Stats, Auth, Health`; `Tag` = play tags and game tags (`/api/game-tags`, `/api/parties/{id}/game-tags`) for autocomplete/filtering; `Game` = party games (`/api/parties/{id}/games…`, enrolment `game-links`) + editing/deleting a shared game (`/api/games/{id}`, games admin only)); input via `#[MapRequestPayload]` DTOs in `src/Dto`.
- `src/Security` – `PartyVoter` (`PARTY_VIEW`/`PARTY_WRITE`/`PARTY_ADMIN`; roles member/recorder/admin (`admin` in code), ADR 0017), `JsonEntryPoint` (401 JSON), `SessionLoginAuthenticator`.
- `src/EventListener/ApiExceptionListener` – errors under `/api` as JSON `{error, violations?}` (`DomainException` → 422, DB unique violation → 409).
- `migrations/` – a single initial migration with a clean schema (ADR 0026; data is not carried over by migration). After changing entities, generate a new migration (`doctrine:migrations:diff`); before the first deployment the migrations can be squashed again using the procedure from ADR 0026.
- Tests (ADR 0022): `tests/Unit` – everything without a DB (controllers, services, DTO validation, voter; `EntityManager`/repositories are mocks), `tests/Support` – `Fixtures` (entities with `id`, `Fixtures::date()`), `DoctrineMocks`, `InMemorySessions` (session repository over an in-memory array), `ControllerHarness` (calls controller actions directly with the real voter and `#[IsGranted]`).

## Frontend – overview
- `src/api` (client + types + endpoints; `queryKeys.ts` = query key factory `qk`, always use it instead of hand-written arrays) · `src/queryClient.ts` (`createQueryClient`, shared by the app and tests) · `src/lib` (pure logic: `playForm`, `gameForm`, `scoring`, `activeParty`, `afterLogin` (`peek`/`clearAfterLoginPath`), `datetime`, `text`) · `src/pages` · `src/components` (`Skeleton`, `GameHeader`, `Autocomplete`, `TagInput`, `PageState` (not found/no permission/loading), `Popup` (base of all popups; `#root` is inert while open), `GameListView`, …); `GameFormPage` and the cheatsheet page are loaded lazily (React.lazy) · `src/AppContext.tsx` (me, parties, active party) · `src/App.tsx` (routes + gating login → nickname → party).
- The version shown at the bottom of the menu (`__APP_VERSION__`, declared in `src/env.d.ts`) is injected by `vite.config.ts` from `git describe --tags` – exactly `v1.0.0` when built on a release tag, `v1.0.0-<n>-g<hash>` between releases; so production must be built from the checked-out tag.
- Mobile-first, max. width 400 px, UI in Czech; Material Symbols icons are loaded only for the listed names – a new icon must be added to `icon_names` in `frontend/index.html`; tests: shared cleanup in `test/setup.ts`, helpers `BASE_ROUTES`, `games`, `sentBody`; look and feel taken over from the old prototype (ADR 0008). Routes (ADR 0009): `/` game list (search, filter; the old `/games` redirects to `/`), `/games/:id` game detail with plays, `/games/:id/cheatsheet|edit`, `/games/:id/new-play` (new play, only from the game detail), `/games/new` (BGG search first, a custom game only when not found; ADR 0021), `/manage/games`, `/plays/:id/edit` (editing a play; deleting and moving it to another party (ADR 0028, admin only) are below the form), `/my-stats` (My statistics ("Moje statistiky") of the logged-in player in the active party, ADR 0031; API `/api/parties/{id}/stats/me`), `/parties/:id/stats` (party statistics; the game and tag filter is in the URL parameters `games`, `excludeGames`, `tags`, `excludeTags`, ADR 0024; the old `/stats` redirects to the active party), `/parties` (party management: list, switching, creating), party management has the tabs Members ("Členové") / Guests ("Hosté") / Settings ("Nastavení") (ADR 0016): `/parties/:id` (members, roles, invitations, leaving), `/parties/:id/guests` (guests: adding, renaming, deleting unused ones), `/parties/:id/edit` (name and abbreviation, admin only).

## Conventions and pitfalls
- Terminology in the UI and documentation: *Party* = **parta** (not "skupina"), switching = "Přepnout" (Switch), button "Vytvořit novou partu" (Create a new party). In code it stays `party` in English.
- Domain rules belong in entities/`Domain`, not in controllers; controllers return `Presenter` arrays.
- `list<DTO>` in DTOs works only thanks to `phpdocumentor/reflection-docblock` + `phpstan/phpdoc-parser` (without them the arrays are not deserialized into objects).
- Tests do not touch the DB (ADR 0022), the whole suite runs in ~1 s. What lives only in SQL/DQL (sorting/searching games, statistics, `PlayRepository`, `statsFor`, unique constraints, migrations) is not tested automatically – when changing these queries, verify them manually with read-only queries against the DB (it is production, write nothing). Final classes are mocked thanks to `dg/bypass-finals`. New controller/service logic: a unit test with mocks, via `ControllerHarness::as($user)->call($controller, 'action', [...])`.
- The games cheatsheet is Markdown (from the earlier import) or user-supplied HTML → always via `renderCheatSheet` + `SafeHtml` (marked + DOMPurify).
- Session numbers (`game_session.number`) are stored, not derived (old numbers have gaps); a new session gets its number from `SessionAssigner` (max+1).
- Games (ADR 0023): `game` is a shared catalog without a party, games are enrolled into a party via `PartyGame` (`Party::addGame/hasGame/findGameLink`); a game with a `bgg_id` is in the catalog only once. Shared data may be changed only by `ROLE_GAMES_ADMIN`; a party member only enrols/removes a game and edits the party game's own players. A game's statistics/plays are always taken only for the given party. Game tags (ADR 0024) belong to the game in the catalog (edited by the games admin), statistics are filtered by games and tags (`StatsFilter`, `?games[]=&excludeGames[]=&tags[]=&excludeTags[]=`). The frontend reads a game via `useGame(id)` (`/api/parties/{id}/games/{gameId}`).
- BGG (ADR 0021): the API requires a registered application and `BGG_API_TOKEN` (without it only the party and the cache are searched). The BGG image is not stored on the server – the preview comes from the CDN, cropping in the browser goes through the proxy `/api/bgg/image`, and only the cropped result is stored locally (ADR 0020). Tests use `FakeBggClient`.
- Game images (ADR 0020): internally WebP only; `POST /api/parties/{id}/game-images` (cropping to a square and WebP encoding is done by the browser; without support (iPhone) it sends JPEG and the server converts it via GD – which in the dev container has no WebP/JPEG, see ADR 0020; `ImageCropPopup` + `react-easy-crop` + `cropToBlob`), files in `web/uploads/covers/<sha1>.webp` (git-ignored, URL `/uploads/…`; in production the web server must serve them and they must be backed up). `game.image_url` may only be such an address; a manual URL no longer exists. The backup of old covers (`/legacy-covers/`) was deleted (ADR 0029). Frontend static files are served under `/static/` (Vite `base`).
- Git: branch `master`, commits with the `Co-Authored-By` trailer as given by the environment. Remote `origin` = `git@github.com:krencl/hesk.git` (private repo); push works with the SSH key `/workspace/github-ssh-key` (in `.gitignore`, **never commit or print it**), which is wired into the local `core.sshCommand` (+ verified host fingerprint in `.git/github_known_hosts`; set it up again after a new container). Push only on explicit request.
