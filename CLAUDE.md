# CLAUDE.md – HESK (zápisy z deskových her)

Webová aplikace pro zapisování výsledků z hraní deskových her a statistiky party hráčů. Komunikace s uživatelem **česky**. Všechny změny commitovat do gitu; architektonická rozhodnutí zapisovat do `docs/adr/` (viz `docs/README.md`).

## Struktura repa
- `web/index.php` – hlavní rozcestník v kořeni (`/api` → Symfony s project_dir `backend/`, jinak SPA `web/static/index.html`); `web/static/` – statika = build frontendu (git-ignorováno).
- `backend/` – Symfony 7.4 LTS, PHP ≥ 8.4, Doctrine ORM (MariaDB 11), PHPUnit. REST API pod `/api`.
- `frontend/` – React 19 + TypeScript + Vite, TanStack Query, React Router, Vitest.
- `docs/` – ADR + poznámky. `/hesk-dev-old` (rozpracovaný prototyp, mimo repo) a `/hesk-original` (produkce, Node/RethinkDB) jsou **jen vzor**, ne součást nové app.

## Příkazy
- Import ze staré aplikace (opakovatelný, ADR 0012; obálky nekopíruje): `cd backend && php bin/console app:legacy:import --dry-run --no-debug -v`, pak bez `--dry-run`. Přístupy `LEGACY_DB_*` jsou v `backend/.env.dev.local` (git-ignorováno, nevypisovat).
- Backend: `cd backend && composer install && php bin/phpunit` · dev server z kořene: `php -S 127.0.0.1:8000 -t web web/index.php` (API + statika + SPA fallback) · DB `docker compose up -d database` + `php bin/console doctrine:migrations:migrate`.
- Frontend: `cd frontend && npm install && npm test` · `npm run dev` (proxy `/api` → :8000) · `npm run build` (včetně `tsc`, výstup do `/web/static`).
- Konfigurace: kořenový `/workspace/.env` (git-ignorováno, root-owned, **obsahuje secrets – nikdy necommitovat ani nevypisovat**) je přes symlink `backend/.env.local` načten Symfony (`DB_*`, `OAUTH_GOOGLE_*`). Viz ADR 0006. DB je **MariaDB 11 – dev databáze**, majitel povolil s ní libovolně nakládat (má zálohu). Obsahuje migrovaná data staré aplikace (tabulky `legacy_*` zůstaly pro kontrolu, ADR 0007). Bez Google klíčů lze ve vývoji použít `POST /api/auth/dev-login` (login formulář ve Vite dev módu).

## Prostředí (tento remote kontejner)
Není tu MySQL ani sudo. PHP 8.4 je systémové (`/usr/bin/php`, s GD vč. WebP/JPEG a `pdo_mysql`/`pdo_sqlite`; po restartu kontejneru bylo k dispozici samo; dříve statický binár z `dl.static-php.dev`, viz ADR 0001); `composer` v PATH není (stáhnout `composer.phar` z getcomposer.org mimo projekt; `zip`/`unzip` jsou nainstalované (`/usr/bin`), takže `composer install/require` funguje normálně, bez `--prefer-source`). MySQL tu neběží, proto testy používají SQLite. Chromium (headless shell) **funguje**: je v `~/.cache/ms-playwright/chromium_headless_shell-*/…/chrome-headless-shell` (`PLAYWRIGHT_BROWSERS_PATH` není nastavené, spouští se přes `executablePath`; knihovna `playwright-core` se instaluje mimo projekt, např. do scratchpadu). Postup: `npm run build`, `php -S 127.0.0.1:8000 -t web web/index.php`, přihlášení přes `POST /api/auth/dev-login` (existující e-mail, ať v dev DB nevznikají zbytečné účty) a screenshot mobilního viewportu.

## Backend – orientace
- `src/Entity` – `User (role v `roles`; `ROLE_GAMES_ADMIN` = správce her), Party, PartyMember, PartyInvitation, Player (hráč party, i host bez účtu), Game (sdílený katalog her, ADR 0023), PartyGame (hra zařazená v partě + vlastní hráči hry), GameAddon (rozšíření), GameCharacter (postavy), Tag, GameSession, Play, PlayResult`.
- `src/Domain` – čistá logika: `ResultCalculator` (pořadí/vítězové dle `ScoreType`), `PlayerInput/Outcome`, `Exception/DomainException` (→ HTTP 422).
- `src/Service` – `CoverStorage` (upload obrázků her), `PlayService` (create/update/delete zápisu), `GuestMerger` (host → člen, ADR 0018), `SessionAssigner` (24h seance, návrh čísla, ruční číslo; ADR 0013), `Bgg/BggClient` + `BggCatalog` (hledání her: hry party → cache `bgg_game` → BGG API, `BGG_API_TOKEN`; ADR 0021), `Presenter` (entity → JSON). `php bin/console app:user:role <e-mail> [ROLE] [--remove]` přidělí roli (správce her).
- `src/Controller` – tenké kontrolery (`Party, Game, Bgg, Play, Tag, Stats, Auth, Health`; `Tag` = seznam tagů pro našeptávání; `Game` = hry party (`/api/parties/{id}/games…`, zařazení `game-links`) + úprava/smazání sdílené hry (`/api/games/{id}`, jen správce her)); vstup přes `#[MapRequestPayload]` DTO v `src/Dto`.
- `src/Security` – `PartyVoter` (`PARTY_VIEW`/`PARTY_WRITE`/`PARTY_ADMIN`; role člen/zapisovač/správce (v kódu `admin`), ADR 0017), `JsonEntryPoint` (401 JSON), `SessionLoginAuthenticator`.
- `src/EventListener/ApiExceptionListener` – chyby pod `/api` jako JSON `{error, violations?}`.
- `migrations/` – `…000000` přejmenuje legacy tabulky, `…000100` schéma, `…000200` import dat ze staré app. Po změně entit vygenerovat novou migraci (`doctrine:migrations:diff`, `schema_filter` ignoruje `legacy_*`).
- Testy (ADR 0022): `tests/Unit` – vše bez DB (kontrolery, služby, DTO validace, voter; `EntityManager`/repozitáře jsou mocky), `tests/Support` – `Fixtures` (entity s `id`), `DoctrineMocks`, `ControllerHarness` (volá akce kontrolerů přímo se skutečným voterem a `#[IsGranted]`); jediný test s DB je `tests/Functional/LegacyImportTest` (SQLite).

## Frontend – orientace
- `src/api` (klient + typy + endpointy) · `src/lib` (čistá logika: `playForm`, `scoring`, `activeParty`, `afterLogin`, `datetime`) · `src/pages` · `src/components` (`Skeleton`, `GameHeader`, `Autocomplete`, `TagInput`, …) · `src/AppContext.tsx` (me, parties, aktivní parta) · `src/App.tsx` (routy + gating login → přezdívka → parta).
- Mobile-first, max. šířka 400 px, UI v češtině; vzhled převzatý ze starého prototypu (ADR 0008). Routy (ADR 0009): `/`→`/games` seznam her (hledání, filtr), `/games/:id` detail hry se zápisy, `/games/:id/cheatsheet|edit`, `/games/:id/new-play` (nový zápis, jen z detailu hry), `/games/new` (nejdřív hledání v BGG, vlastní hra až když se nenajde; ADR 0021), `/manage/games`, `/plays/:id/edit` (úprava zápisu, smazání je pod formulářem), `/stats`, `/parties` (správa part: seznam, přepnutí, založení), správa party má záložky Členové / Hosté / Nastavení (ADR 0016): `/parties/:id` (členové, role, pozvánky, opuštění), `/parties/:id/guests` (hosté: přidání, přejmenování, smazání nepoužitých), `/parties/:id/edit` (název a zkratka, jen správce).

## Konvence a pasti
- Terminologie v UI i dokumentaci: *Party* = **parta** (ne „skupina“), přepínání = „Přepnout“, tlačítko „Vytvořit novou partu“. V kódu zůstává anglicky `party`.
- Pravidla domény patří do entit/`Domain`, ne do kontrolerů; kontrolery vrací `Presenter` pole.
- `list<DTO>` v DTO funguje jen díky `phpdocumentor/reflection-docblock` + `phpstan/phpdoc-parser` (bez nich se pole nedeserializují na objekty).
- Testy nesahají do DB (ADR 0022), celá sada běží ~1 s. Co je jen v SQL/DQL (řazení/hledání her, statistiky, `PlayRepository`, `statsFor`, unikáty, migrace) automaticky netestujeme – při změně těchto dotazů je ověřit ručně proti dev DB. Final třídy se mockují díky `dg/bypass-finals`. Nová logika kontrolerů/služeb: unit test s mocky, přes `ControllerHarness::as($user)->call($controller, 'akce', [...])`. `LegacyImportTest` je výjimka (SQLite, `SqliteNoFsyncMiddleware` vypíná fsync).
- Cheatsheet her je Markdown (import ze staré app) nebo HTML od uživatelů → vždy přes `renderCheatSheet` + `SafeHtml` (marked + DOMPurify).
- Čísla seancí (`game_session.number`) jsou uložená, ne odvozená (stará čísla mají mezery); novou seanci číslo přiřadí `SessionAssigner` (max+1).
- Hry (ADR 0023): `game` je sdílený katalog bez party, do party se zařazují přes `PartyGame` (`Party::addGame/hasGame/findGameLink`); hra s `bgg_id` je v katalogu jen jednou. Sdílená data smí měnit jen `ROLE_GAMES_ADMIN`, člen party hru jen zařadí/odebere a mění vlastní hráče hry party. Statistiky/zápisy hry se vždy berou jen za danou partu. Frontend čte hru přes `useGame(id)` (`/api/parties/{id}/games/{gameId}`).
- BGG (ADR 0021): API vyžaduje registrovanou aplikaci a `BGG_API_TOKEN` (bez něj se hledá jen v partě a v cache). Obrázek z BGG se neukládá na serveru – náhled je z CDN, ořez v prohlížeči jde přes proxy `/api/bgg/image` a lokálně se uloží až výřez (ADR 0020). Testy používají `FakeBggClient`.
- Obrázky her (ADR 0020): interně jen WebP; `POST /api/parties/{id}/game-images` (ořez do čtverce a kódování do WebP dělá prohlížeč, bez podpory (iPhone) pošle JPEG a převede ho server přes GD – ta v dev kontejneru nemá WebP/JPEG, viz ADR 0020; `ImageCropPopup` + `react-easy-crop` + `cropToBlob`), soubory v `web/uploads/covers/<sha1>.webp` (git-ignorováno, URL `/uploads/…`; v produkci je musí servírovat web server a zálohovat se). `game.image_url` smí být jen taková adresa; ruční URL zaniklo. Staré obálky z `frontend/public/covers/` (git-ignorováno) jsou už převedené, zůstaly jen jako záloha. Statika frontendu se servíruje pod `/static/` (Vite `base`).
- Git: větev `master`, commity s trailerem `Co-Authored-By` dle zadání prostředí. Remote `origin` = `git@github.com:krencl/hesk.git` (privátní repo); push jde SSH klíčem `/workspace/github-ssh-key` (v `.gitignore`, **nikdy necommitovat ani nevypisovat**), který je zapojený v lokálním `core.sshCommand` (+ ověřený otisk hostitele v `.git/github_known_hosts`; po novém kontejneru nastavit znovu). Pushuje se jen na výslovné vyžádání.
